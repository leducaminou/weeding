---

# 22. IDENTIFIANT INVITÉ

Chaque personne confirmée reçoit un identifiant unique.

Format strict :

```text
2 lettres + 2 chiffres
```

Exemples :

```text
AB42
LO27
FR19
```

L'identifiant doit être :

* unique ;
* généré côté serveur ;
* vérifié côté DB ;
* impossible à dupliquer.

Ne pas générer uniquement côté frontend.

Prévoir une stratégie de collision.

---

# 23. QR CODE

Après confirmation, générer automatiquement un QR Code personnel.

Le QR Code doit contenir uniquement une URL :

```text
https://DOMAIN/qr/AB42
```

Ne PAS mettre directement :

```text
Nom
Prénom
Téléphone
```

dans le QR.

Le serveur utilise l'identifiant pour retrouver l'invité.

---

# 24. DIMENSIONS QR

Chaque QR Code doit être :

```text
webp
320 × 320 px maximum
```

Recommandation :

```text
320 × 320 px
```

Le fichier doit être propre et parfaitement scannable.

Conserver une quiet zone suffisante.

---

# 25. UPLOADTHING

Chaque QR Code doit être uploadé sur UploadThing.

En DB, conserver au minimum :

```text
qrCodeUrl
qrCodeKey
```

afin de pouvoir supprimer précisément le fichier plus tard.

Ne jamais dépendre uniquement de l'URL.

La confirmation RSVP ne doit jamais dépendre de WhatsApp.


* l'invité reste confirmé ;
* le QR reste valide ;
* le dashboard affiche l'erreur ;
* l'administrateur peut renvoyer le message.

Il sert à identifier l'invitation.

Prévoir une stratégie de validation raisonnable.

# 63. SUPPRESSION AUTOMATIQUE DES QR CODES

Tous les QR Codes UploadThing doivent être supprimés après :

# 15 JANVIER 2027

Implémenter une vraie tâche serveur/cron.

Ne pas dépendre du navigateur.

Le cleanup doit :

1. rechercher les QR à supprimer ;
2. supprimer les fichiers UploadThing ;
3. mettre à jour la DB ;
4. journaliser ;
5. gérer les erreurs ;
6. être idempotent.
